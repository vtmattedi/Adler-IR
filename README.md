# Adler

Adler controls an IR air conditioner using a DS18B20 room thermometer and an optional door Value owned by another NightMare Network device. It builds against the rewritten library in `../nightmarenetwork` and uses the cluster-local MQTT broker. The backend belongs on the bridged remote side of the network.

## Build and configure

Copy `include/creds.example.h` to ignored `include/creds.h`, then set Wi-Fi, local MQTT, and OTA credentials. The checked-in template contains placeholders. Build with `pio run -e esp32c3-supermini`; the classic ESP32 wiring record has `pio run -e esp32doit-devkit-v1`.

The device reads its existing LittleFS `/configs.json` on boot. It retains `_device_name`, `_ssid`, `_password`, `door_device`, `door_key`, `door_invert`, `ir_debug`, and `ac_*` settings. Missing Wi-Fi settings use the values in `creds.h`. A generated `Adler-<MAC>` name is used when `_device_name` is absent or invalid. Resource and device IDs must use letters, digits, `_`, `-`, or `.`.

The `Time-master` vendor library remains in `lib/` as historical source and is excluded by `lib_ignore = Time`; the active firmware uses the NightMare system UTC time adapter. The old command resolver, direct MQTT publications, sensor inbox, and `description.json` are gone.

## Resources

The `nm/default/<device>/r/<resource>/<operation>` topics and schemas are generated by the Resource Manager. Console input at `<device>/console/in` and the serial console invoke the same registered Actions. A local MQTT broker receives the device's schema and authoritative Value state; no application module constructs resource topics.

| Resource | Kind | Meaning |
| --- | --- | --- |
| `temperature`, `temperatureConnected`, `temperatureAddress` | Values | Last good DS18B20 reading and current sensor connection |
| `irLastCode`, `irRawCode`, `irReceived` | Values, Event | Last decoded IR frame and each new frame |
| `acState`, `acPower`, `acUnitTemperature`, `acMode`, `acTarget` | Values | AC belief and controls; the latter four accept writes |
| `sleepIn`, `doorPaused`, `doorState`, `sleepRemaining` | Values | AC timing and door policy; first two accept writes |
| `firmwareVersion`, `boardName`, `uptime`, `irDebug` | Values | Device information and IR debug state; `irDebug` accepts writes |
| `temperatureLost` | Event | Sensor became disconnected after being found |
| `sendIr`, `manualSync`, `setSleepMinutes`, `morningOff` | Actions | IR and AC commands |
| `rescanTemperature`, `probeDs18` | Actions | Sensor diagnostics |
| `configureDoor`, `configureAc` | Actions | Persisted source and policy configuration |

Writes go to the corresponding `.../write` topic. The owner validates and applies each request, then publishes the actual state on `.../state`. Value state remains the last known reading; `temperatureConnected=false` says the thermometer has since been lost.

Actions use the new wire codec. For example, `sendIr` takes a String argument encoded as `~POWER`; `manualSync` takes `[true,24]`; `setSleepMinutes` takes `30`; `morningOff` takes `true` to force the shutdown. `probeDs18` returns a JSON diagnostic result. The serial console accepts the same argument after the Action ID, such as `manualSync [true,24]`.

`configureAc` takes `["ac_hysteresis","0.5"]`, with keys `ac_hysteresis`, `ac_door_pause_secs`, `ac_door_stop_secs`, `ac_door_control`, `ac_turn_off_time`, `ac_sleep_in_turn_off_time`, `ac_default_target`, and `ac_utc_offset_minutes`. Times use `HH:MM` at the configured fixed UTC offset, which defaults to `-180` minutes. The Scheduler converts them to UTC calendar Jobs and waits until the clock is valid. DST rules are not inferred.

`configureDoor` takes `["owner-device","door",false]`. It saves the owner, resource ID, and inversion flag, then restarts after the ACK so the mirror is registered with its new address. Empty owner and resource strings unbind the door. The source device should publish the boolean door Value periodically. Adler treats it as unknown before the first state and after 10 minutes without a valid state update; it never assumes stale means closed. A 10 second owner heartbeat with a 30 second consumer threshold is a reasonable tighter policy, but Adler currently uses the existing 10 minute control window.

## Runtime

One manually driven Runtime polls Wi-Fi, MQTT dispatch, serial input, the nonblocking DS18B20 conversion, and IR send/receive. Scheduler Jobs run the AC policy every two seconds and refresh Resources every second. NightMare's network queue moves MQTT callbacks onto the Runtime thread. OTA is also polled after Wi-Fi connects. No sensor or AC task is created.

Hardware verification still requires a deployed board, local broker, DS18B20, IR receiver/transmitter, and a remote door publisher. The PlatformIO build checks compilation and linking only.
